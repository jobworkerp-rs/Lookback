# チャットで内部 Issue を操作する

チャットでは内部 Issue の検索・詳細表示・作成・編集・取消を依頼できます。GitHub/Gitea の Issue とは別の、Lookback が管理する作業項目です。Issue Tracker が有効で利用可能なときに使えます。

## ツール実行の許可を設定する

1. チャット画面の「ツール実行に許可を必要とする」を確認します。初期状態は ON です。
2. ON の場合、記憶検索を含む**各ツール呼出しの前に**ツール名と引数を確認し、許可または拒否を選びます。拒否した呼出しは実行されません。
3. OFF にすると、承認待ちのツールも許可し、以後のツール呼出しを個別確認なしで実行します。Issue の作成・編集・取消も含まれるため、必要なときだけ選択してください。Issue 本文などに悪意のある指示が埋め込まれていた場合の誤操作を完全には防げません。この設定は次回起動時にも引き継がれます。

ツール実行を許可することと、Issue の内容を「確認済み」と判断することは異なります。内容を確認したいときは、チャットで提示された Issue の内容に対して回答してください。

## Issue を調べて整理する

1. 例: 「現在の Issue の中から、この件に関係するものを探して詳細を比べて」と依頼します。Issue の一覧と関係は一度にすべて返さず、次ページがある場合は返された token を使って続きを取得します。
2. 更新・取消の前には対象の詳細をそのチャットの発話内で取得して revision を確認します。重複整理なら「重複した Issue を調べ、残すものと取り消すものを根拠付きで決めて」と依頼します。取消対象と残す Issue の両方を詳細取得して比べてください。必要なら残す Issue を更新した後、重複する Issue を取り消します。これは Issue 同士の内容や証拠の自動マージではありません。
3. ツール実行の許可が ON なら、表示される操作の対象 ID と引数を確認して許可します。意図と違う場合は拒否し、チャットで訂正します。

作成・更新・取消が確定した場合は、LLM の文章とは別に Issue ID、操作の確定状態、監査理由を表示します。回答が途中で止まった場合も、この操作結果を確認してください。

新規 Issue は「この内容を Issue にして」と依頼できます。人間からの依頼を代行した作成は出典となる既存の記憶を必須としません。LLM 自身の判断に基づく起票には既存の検証可能な記憶の出典が必要です。「選択した記憶だけ」のチャットでも Issue 作成は利用できますが、追加の Issue 一覧・詳細取得は使えません。

## 失敗・中断したとき

revision 競合や処理結果が不明な場合、表示された Issue ID と操作状態を確認してください。同じ操作を別の依頼として繰り返すと重複する可能性があります。チャットの停止や画面を閉じる操作は、すでに受け付けられた Issue の変更を取り消しません。未確定の操作がある場合はチャット画面の「未確定の Issue 操作」を開き、対象 ID と操作を確認してから「結果を確認・再送」を押します。同じ保存済み要求を使って確認・再送するため、新しい依頼として起票し直さないでください。結果が確定できなければ操作は保留のまま残ります。複数 Issue の整理が途中で止まった場合は、完了した対象と未処理の対象を区別して確認します。
## Issue Tracker を無効にした場合

設定で Issue Tracker を無効にすると、チャットおよび外部 MCP の Issue ツールは登録一覧から除外されます。以前に登録した Issue Worker も削除され、記憶検索ツールは利用できます。再度有効にすると Worker とツールを再登録します。設定が有効なまま Issue Tracker サーバーに接続できない場合はツールの登録を維持し、呼び出し時に利用不可を返します。

切替中に登録状態の更新・照合に失敗した場合、無効化は成功として報告されません。無効設定のまま旧登録を使用できる sidecar は停止します。設定変更がロールバックされる場合は、元の設定で再起動し、登録状態を復元します。未確定の Issue 操作は自動的に取り消されないため、上記の「未確定の Issue 操作」で結果を確認してください。
